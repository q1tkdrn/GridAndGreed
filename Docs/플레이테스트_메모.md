# 플레이테스트 메모 (2026-11-03, Claude)

다른 AI·작업자가 이어서 고칠 수 있게 쓴 메모. 각 항목: 어디서 / 무엇이 / 왜(파일) / 제안.
프로젝트: Unity 6000.3, 작업 브랜치 JSW. 씬 흐름: Start → Opening → BattleTemp(튜토리얼) → Main(마을, 여정 지도 포함) → Item·Character·Skin 등 상점 씬 → BattleTemp(보스전).
테스트 범위: 새 게임 → 오프닝 → 튜토리얼 → 마을 → 아이템 상점 → 여정 지도 → 훈련장(교관) 전투 패배 → 마을 → ESC 메뉴 → 다시 훈련장 승리(보스 HP 1로 조작) → 여정 지도.
주의: 전투는 코드로 조작해서 했다. 튜토리얼이 대본보다 1턴 길어진 것, 정보창이 남아 있던 것은 조작 탓이라 아래에 넣지 않았다.

## 1순위: 막히거나 헷갈리는 것

1. 승리 화면 '상관없음' 버튼
   - 보상(소울 500)을 받지 않고도 눌러서 넘어갈 수 있다 → 보상을 놓칠 수 있음. 보상을 받은 뒤에도 버튼 글자가 '상관없음'으로 남는다.
   - 파일: Assets/Sanggu/Scripts/BattleDisplayManager.cs (AddRewardText(skipBubble, "상관없음") 근처, ClaimVictorySoul)
   - 제안: 글자를 '계속'으로. 누르면 안 받은 보상은 자동 지급(또는 '보상을 받지 않고 넘어갈까요?' 확인).

2. 패배 화면
   - '나가기' 위에 글자 없는 ▶ 버튼이 하나 더 있다(빈 화살표).
   - '다시 도전'이 없다. '나가기'를 누르면 여정 지도가 아니라 마을로 가고, 마을은 마지막에 보던 페이지(상점 쪽)로 열린다.
   - 패배 분석 상자: 글이 왼쪽 위에 몰리고 아래 절반이 비어 있다. 제목 '패배 분석, 교관'의 쉼표가 어색('패배 분석 · 교관'). '확인' 버튼이 납작한 회색이라 안내문 창(Assets/Resources/UI/PauseMenu.prefab, ModalDialog) 스타일과 다르다.
   - 제안: 빈 ▶ 제거, 확인 버튼을 안내문 버튼 그림(Assets/JSW/UI/Notice/안내문_버튼.png)으로, '나가기' → 표준 '돌아가기'.

3. 오프닝 건너뛰기·넘기기
   - 오른쪽 아래 '[space]를 눌러 스킵'(Skip Button)에 클릭 연결이 없다 → 마우스로는 못 건너뜀.
   - 다음 문장은 ▼ 버튼만 눌러야 넘어간다(화면 아무 곳 클릭·Enter 안 됨). ▼가 글의 왼쪽에 있어 눈에 잘 안 띈다.
   - 파일: Assets/JDY/Scripts/.../OpeningManager.cs (Keyboard.current가 null이면 오류 가능), OpeningUI.cs
   - 제안: 화면 클릭·Enter·Space(한 번=다음 문장, 길게=건너뛰기), Skip 버튼에 TutorialLink.Begin 연결, 문구 '[Space] 건너뛰기', ▼는 글 오른쪽 아래.

4. 할 일이 없는 턴 (기획 제안)
   - 턴 종료 버튼이 없어서, 힘 칸을 다 먹은 뒤엔 남은 행동력을 의미 없는 이동으로 다 써야 턴이 넘어간다. 구석에 몰리면 갈 수 있는 칸이 전부 공격 칸인 경우도 나왔다.
   - 제안(턴 종료 버튼 없이): 캐릭터를 제자리에서 한 번 클릭 = '대기'(행동력 1). 궁수 특성(움직이지 않으면 피해 +8)과도 맞물려서 선택지가 생긴다.

5. 새 게임 직후 소울 0
   - 튜토리얼이 '소금물'을 소개하는데, 끝나고 상점에 가면 소울 0이라 살 수 없다(소금물 300).
   - 제안: 튜토리얼 완료 때 소울 300 지급(또는 첫 상점 방문 때 '여정에서 소울을 모으세요' 안내).
   - 참고: 업적 보상이 커서 한 판(패배 1, 승리 1) 만에 0 → 2,700이 됐다. 경제 밸런스 확인 필요 (AchievementManager.cs AddSoul).

## 2순위: 화면·가독성

6. 전투 칸 위 글자 겹침: 욕심 칸에서 버티는 캐릭터는 한 칸에 '버티면+7' 상자 + 위쪽 심판 피해 숫자 + 캐릭터 그림이 겹친다. 파일: Assets/JSW/Script/Trial/BellkeeperTrial.cs (RefreshMarkers, RefreshChargeLabels). 제안: '버티는 중'은 칸 테두리 금색 깜빡임이나 작은 아이콘으로.
7. 욕심 칸 그림이 공격 예고(회색 0.65)에 덮여 흐리다. 욕심 칸은 항상 공격 범위 안에 생기므로 늘 흐림. 제안: 욕심 칸 위치에서는 예고를 테두리만 그리기.
8. 마을: 소울이 화면에 안 보인다(상점에 들어가야 보임). NPC 이름표 글씨가 작다(약 14px 상당). 왼쪽 튜토리얼 NPC는 이름표가 없어 누를 수 있는지 모른다. NPC가 흰색/분홍(캐릭터 상점 릴리만) 단색 실루엣이라 '마우스 올림 표시'인지 '미완성 그림'인지 구분이 안 된다 → 의도 확인.
9. 마을 상점 페이지: '캐릭터 상점 - 릴리' 띠와 '아이템 상점 - 아스터' 띠가 겹친다.
10. 상점: 나가는 버튼이 '나가기'(Item 씬 Exit Button) → 게임 표준 '돌아가기'(WaysBack)와 다름. 가격 '300'에 단위가 없다('300 소울' 또는 소울 아이콘).
11. ESC 메뉴(EscMenu.cs): '타이틀화면으로'가 붓 배너 밖으로 넘친다. 띄어쓰기 '타이틀 화면으로'. 다른 버튼은 '설 정', '종 료'처럼 자간을 띄워 놓아 통일이 안 된다.
12. 여정 지도(JourneyMap.cs): 다음에 갈 수 있는 곳 표시가 없다. 클리어한 곳의 빨간 X가 이름표 앞부분을 가린다. 안개가 이전에 보였던 장소(연구소)를 다시 가린다(의도인지 확인). 남은 HP·처치 수가 지도에 안 보이고, 편성 버튼은 잠깐 뒤 사라진다(HideFormationButtonSoon).
13. 승리 화면: '보상' 말풍선은 글자표인데 버튼처럼 생겼다. 업적 달성 알림이 '상관없음' 말풍선과 겹친다.
14. 타이틀: 메뉴 글자가 왕 그림 몸통 위에 겹쳐 읽기 어렵다. 글자 뒤에 옅은 그림자나 띠 추천.
15. 전투 시작 첫 순간에 '15 / 15', '60 / 60', '의지력: 15' 같은 기본값이 읽혔다(튜토리얼 시작 직후). 한 프레임 깜빡임일 수 있음 → 시작 전에 글자를 비우거나 숨기기.
16. 전투 왼쪽 아이템 칸 3개가 비어 있으면 그냥 검은 네모 → '빈 칸' 표시나 흐린 테두리.

## 3순위: 글

17. 오프닝 문장(OpeningUI content): 끝 공백·두 칸 공백이 섞여 있다. '이 때' → '이때'(마지막 문장의 '그때'와 맞춤).
18. 말투 섞임: 스테이지 입장 '스테이지에 입장하시겠습니까?'(합쇼체) / 다른 안내는 해요체·반말. 해요체로 통일 추천('들어갈까요?').
19. 튜토리얼 문서(claude.ai Project의 claude/tutorial_status.md)가 실제와 다르다: 안내자 HP 실제 43(문서 47), '소금물' 아이템 설명 단계가 추가됨.

## 확인 방법 (Unity 에디터 + 코드 조작)
- 세이브는 PlayerPrefs(레지스트리 HKCU\Software\Unity\UnityEditor\DefaultCompany\GridAndGreed). 테스트 전 `reg export`로 백업, 끝나고 `reg delete` 후 `reg import`. 캐릭터 에셋(UnitTemp)의 스킨 잠금 값도 테스트 전후 비교.
- 오프닝은 TutorialLink.Begin()으로 넘김. 튜토리얼은 TutorialDirector.Current(act: Next/Select/Place/Drag/Move/Judge)를 보고 OnBubbleClicked / OnUnitInReadyClicked / OnBoardClicked / OnPointerClick 두 번(심판)으로 진행.
- 이동을 코드로 할 때 units 배열은 struct라서 값을 바꾼 뒤 다시 넣어야 한다(units.SetValue).
- 전투 시험: BattleDisplayManager.DebugEnterBoss(보스) → 다음 프레임에 배치 → 칸 생성. 자세한 절차: Project 문서 claude/battle_tile_status.md
- 캡처는 960×540이면 화면 문제 확인에 충분, 칸 글자는 1280×720.
